## Derivatives: Your Processing History

AutoCleanEEG saves your data after each major processing step in numbered folders inside `bids/derivatives/`. This creates a complete audit trail from raw input to cleaned output.

Each folder represents one operation in your pipeline—filtering, ICA, epoching, etc. You can open any step to see exactly what your data looked like at that moment.

## The Numbered Folders

```
bids/derivatives/
├── 01_import/           # Data right after loading
├── 02_resample/         # Resampled to target rate
├── 03_drop_eog_channels/ # EOG channels removed
├── 04_trim/             # Edge artifacts trimmed
├── 05_filter/           # Filtering applied
├── 06_bad_channels/     # Bad channels removed
├── 07_rereference/      # Rereferencing applied
├── 08_artifact_detection/ # Artifacts annotated
├── 09_ica/              # ICA applied
├── 10_pre_ica/          # Before ICA snapshot
├── 11_epochs/           # Initial epochs created
├── 12_drop_bad_epochs/  # Bad epochs removed
├── 13_epochs/           # Final epochs
├── 14_gfp_clean/        # GFP cleaning applied
└── 15_comp/             # Final compiled output
```

The numbering shows the processing order. Lower numbers come earlier in the pipeline.

## What's Inside Each Folder

Each folder contains EEGLAB `.set` files—one for each recording you processed:

```
09_ica/
├── recording1_ica_raw.set
├── recording2_ica_raw.set
└── recording3_ica_raw.set
```

These are complete EEG datasets you can open in EEGLAB or MNE-Python to inspect the data at that processing stage.

## Key Processing Steps

| Step | What Happened |
|------|---------------|
| **01_import** | Your original data, converted to pipeline format |
| **05_filter** | High-pass, low-pass, and notch filters applied |
| **06_bad_channels** | Problematic electrodes identified and removed |
| **09_ica** | Artifacts removed using Independent Component Analysis |
| **13_epochs** | Data segmented into analysis-ready time windows |
| **15_comp** | Final cleaned output, ready for analysis |

## ICA Files: Special Case

The `09_ica/` step contains both EEGLAB `.set` files and MNE `.fif` files:

**EEGLAB format (.set):** ICA weights embedded directly in the dataset

**MNE format (.fif):** ICA weights saved separately (also in the `ica/` folder at the root level)

This dual format lets you work with either EEGLAB or MNE-Python tools, and allows you to re-apply ICA weights to data if needed.

## Dynamic Step Generation

Your specific pipeline might not create all these folders. The steps that appear depend on your task configuration:

- Skip ICA → no `09_ica/` folder
- Skip trimming → no `04_trim/` folder
- Add custom processing block → additional numbered folder appears

Only the operations you actually run create folders.

## Why This Matters

**Debugging:** When results look unexpected, trace back through the steps to find where things changed.

**Verification:** Confirm each operation did what you expected by comparing before/after folders.

**Learning:** See the exact effect of each preprocessing operation on your data.

**Documentation:** Complete record of transformations for methods sections and reproducibility.

## Managing Storage

These derivative files use disk space. After confirming your results look good:

**Essential (keep these):**
- Final data in `exports/` folder
- BIDS subject folders (`bids/sub-*/`)
- All reports and logs

**Optional (can delete to save space):**
- The numbered derivatives folders (01_import through 15_comp)

Your final cleaned data is safe in multiple locations. The derivatives are primarily for verification and debugging.

<Tip>
If you need to check an intermediate step later, you can always re-run the pipeline. The processing is fast, and the task file with all parameters is saved in the `status/` folder.
</Tip>
